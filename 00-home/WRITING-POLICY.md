# Vault 작성·승격 정책

## 목적

이 Vault는 모든 세션을 저장하는 일지가 아니라, 다음 AI가 같은 실수를 반복하지 않도록 검증된 지식을 보존하는 공간이다.

## 어디에 기록할지 결정

| 정보 | 기준 위치 |
|---|---|
| 현재 작업과 다음 행동 | 프로젝트 저장소 `docs/ai/NOW.md` |
| 프로젝트 구조와 진입점 | 프로젝트 저장소 `docs/ai/PROJECT.md` |
| 장기 설계 결정 | 프로젝트 저장소 `docs/ai/decisions/ADR-*.md` |
| 가공 전 세션 기록 | `10-inbox/<agent>/` |
| 프로젝트의 중요 사건 | `20-projects/<project>/incidents/` |
| 완료된 큰 작업 | `20-projects/<project>/milestones/` |
| 프로젝트 종료·단계 회고 | `20-projects/<project>/retrospectives/` |
| 두 프로젝트 이상에서 재사용할 교훈 | `30-patterns/` |
| 사용자 성향·공통 정책 | `40-profile/` |

## 영구 기록으로 승격하는 조건

다음 중 하나 이상일 때만 사건·패턴 노트를 만든다.

- 새로운 근본원인이 확인됐다.
- 같은 문제가 두 번 이상 반복됐다.
- 중요한 구조·아키텍처 결정을 했다.
- 여러 프로젝트에 적용할 수 있는 해결법이다.
- 실패한 접근 방식 자체가 재사용 가능한 교훈이다.
- 보안, 배포, 결제, 데이터 손실 위험이 있었다.
- AI의 오진, 허위 검증, 증거 불일치를 발견했다.

조건에 해당하지 않으면 프로젝트의 `NOW.md`만 갱신한다.

## 증거 우선순위

1. 실제 사용자·실기기·운영 환경 결과
2. 자동화된 테스트와 재현 가능한 명령 결과
3. Git diff와 커밋
4. 로그와 캡처
5. 코드 정적 검토
6. AI의 설명과 자기평가

상위 증거와 하위 증거가 충돌하면 상위 증거를 따른다.

## 상태와 확신도

- `root_cause_status: confirmed`: 재현, 수정, 재검증으로 원인이 확인됨
- `root_cause_status: suspected`: 설명 가능한 가설이나 아직 표적 검증 전
- `root_cause_status: unknown`: 원인 미확인
- `status: active`: 해결되지 않음
- `status: monitoring`: 수정 후 관찰 중
- `status: resolved`: 검증까지 완료

추정 원인을 확인된 사실처럼 쓰지 않는다.

## 작성 규칙

- 폴더와 파일명은 자동화 안정성을 위해 영문 소문자·숫자·하이픈을 우선한다.
- 본문은 한국어로 작성할 수 있다.
- 새 노트는 `_templates/`를 사용한다.
- 작성 AI는 `agents: [claude-code]`처럼 속성에 기록한다.
- 코드 전체를 복사하지 않는다. 파일 경로와 커밋을 우선하고 필요한 짧은 스니펫만 남긴다.
- 원문 대화와 비공개 내부 추론을 저장하지 않는다.
- 완료 시각보다 검증 시각을 중요하게 기록한다.
- 기존 내용을 정정할 때는 조용히 지우기보다 무엇이 바뀌었는지 남긴다.

## Inbox 수명

- `10-inbox/`는 임시 공간이며 기준 정보가 아니다.
- 모든 초안에는 가능하면 `created`, `review_by`, `agents`, `project`를 기록한다.
- [[10-inbox/INBOX-REVIEW]]의 트리거에 따라 검토하며, 기본 `review_by`는 작성 후 7일이다.
- 30일 이상 가치가 확인되지 않은 기록은 `90-archive/`로 옮긴다.
- 다른 AI가 이어받아야 하는 현재 상태는 Inbox가 아니라 프로젝트 `NOW.md`에 둔다.
- AI는 승격·보관 후보를 제안할 수 있지만 자동 삭제하지 않는다.

## 동시 작업

- 가능한 한 AI마다 새 노트를 생성하고 같은 노트를 동시에 편집하지 않는다.
- 프로젝트 코드를 동시에 수정한다면 별도 Git 브랜치 또는 worktree를 사용한다.
- `PROJECT-CARD.md`와 `PROJECT-INDEX.md`는 마일스톤 체크포인트에서만 갱신한다.
- Vault 정책과 구조 변경은 [[VERSION-CONTROL]]에 따라 로컬 커밋으로 남긴다.
