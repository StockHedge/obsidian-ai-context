# 사용자가 직접 기록·갱신할 때

AI가 자동으로 작성할 수 있어도 다음 정보는 사용자가 직접 확인하거나 최종 결정한다.

## 직접 기록이 필요한 경우

- 여러 프로젝트의 우선순위나 중단·재개 결정이 바뀌었을 때
- AI가 알 수 없는 외부 사건이 생겼을 때: 심사 결과, 고객 반응, 결제·계약, 콘솔 변경
- 개인 선호나 Git 권한 정책을 바꾸고 싶을 때
- AI의 기록이 틀렸거나 과장됐음을 발견했을 때
- 어떤 Inbox 초안을 영구 지식으로 승격할지 판단할 때
- 프로젝트 종료, 보관, 삭제를 최종 승인할 때

## 직접 쓰지 않아도 되는 경우

- 평범한 세션 요약
- 코드 diff로 바로 확인되는 수정 내역
- 테스트 결과의 단순 복사
- AI가 이미 `NOW.md`에 정확히 갱신한 현재 상태
- 검증되지 않은 아이디어를 영구 패턴으로 정리하는 일

## 최소 운영 루틴

1. 매주 첫 작업에서 [[10-inbox/INBOX-REVIEW]] 후보를 확인한다.
2. 프로젝트 전환 전에 `NOW.md`가 실제 상태와 맞는지만 확인한다.
3. 정책 변경은 기준 문서에서 먼저 고치고 [[POLICY-DISTRIBUTION]]에 따라 재배포한다.
4. AI가 만든 중요 기록은 코드·Git·실환경 증거와 맞는지 승인한다.

사용자의 역할은 모든 기록을 직접 쓰는 것이 아니라, AI가 알 수 없는 사실과 최종 판단의 소유자가 되는 것이다.
