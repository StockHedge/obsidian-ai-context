# 개인정보처리방침이 존재하지 않는 탈퇴 경로를 안내하고 있었다

## 요약

모바일 앱 스토어 제출을 준비하다가 **회원 탈퇴·계정 삭제 기능이 웹·앱 어디에도 없다**는
것을 발견했다. 그런데 개인정보처리방침 §7 은 `"회원 탈퇴 (대시보드 → 설정 → 탈퇴)"` 를
안내하고 있었다. 대시보드의 "설정"은 알림 설정 모달이다.

## 발견

전수 확인 결과:

| 위치 | 결과 |
|---|---|
| 웹 라우트 `frontend/src/App.tsx` | 탈퇴·계정 삭제 경로 **없음** |
| `backend/app/api/users.py` | DELETE 는 `/notify-phone`(알림번호 해제)뿐 |
| 대시보드 "설정" | 알림 설정 모달 — 탈퇴 아님 |
| 모바일 앱 | 없음 |

## 두 가지 문제

1. **규제 문서의 허위 기재.** 개인정보보호법상 이용자 권리(파기 요구) 행사 방법을 잘못
   안내했다. 이용자가 안내대로 찾다 포기하면 권리 행사가 사실상 봉쇄된다.
   방침 §7 하단에 support 이메일 경로가 있어 완전 부재는 아니었지만, **먼저 눈에 띄는
   안내가 막다른 길**이었다.
2. **Play Store 출시 차단.** Play 는 계정을 만드는 앱에 "계정 삭제 요청 **웹** URL"을
   요구한다. 앱 내부 경로만으로 부족하고, 앱을 설치하지 않은 사람도 열 수 있어야 한다.

## 근본 원인

**규제 문서를 코드보다 먼저, 그리고 코드와 무관하게 썼다.** 방침·약관은 "이렇게 하겠다"는
선언으로 작성되는데 그 선언이 구현됐는지 확인하는 절차가 없었다.

방침은 **테스트되지 않고 린트되지 않는다.** 화면에 잘 렌더되기만 하면 통과한 것처럼
보인다 — 코드에는 있는 안전망이 이 영역에만 통째로 없다.

같은 파일에서 반대 방향 괴리도 함께 나왔다: 휴대폰 번호를 "SHA-256 해시"로 기술했으나
실제 구현은 **HMAC-SHA256**(pepper=`JWT_SECRET`)이었다. 순수 SHA-256 은 한국 휴대폰
번호 공간(~10⁸)이 좁아 유출 시 전수 대입으로 역산되지만 HMAC 은 서버 시크릿 없이
불가능하다. 즉 **구현이 문서보다 안전한데 문서가 스스로를 약하게 기술**하고 있었다.
문서-코드 괴리는 양방향으로 존재했다.

## 조치

- ✅ 방침 §7 을 실제 동작하는 경로(support 이메일 요청 + 법정 보관 대상 제외 명시)로
  정정. 해시 방식 표기도 HMAC-SHA256 으로 정정. (2026-08-17)
- ⏳ 계정 삭제 API + 공개 페이지 `/account/delete` + 앱 내 진입점.
  ⚠️ **하드 삭제가 아니라 익명화 + 법정 보관분 분리**여야 한다 — 방침 §3 이 전자상거래법
  5년/3년, 통신비밀보호법 3개월 보관을 이미 약속했다. 배포된 사이트의 처리(즉시 내림/유예)
  도 함께 정해야 한다.

## 교훈

**규제 문서에 적은 모든 "이용자가 할 수 있는 일"은 실제로 클릭 가능해야 한다.**
방침을 개정하거나 검토할 때 안내된 경로를 **하나씩 따라가 보는 절차**를 넣는다.

새 채널(앱·스토어)을 여는 시점이 이 괴리가 드러나는 자리다 — 심사자가 대신 확인해 준다.
바꿔 말하면, **새 채널을 열지 않으면 영영 드러나지 않는다.**

## 해소 (2026-08-18)

- `POST /api/users/me/delete` + 공개 페이지 `/account/delete` + 앱 진입점 + 방침 §7.1 신설.
  절차 본체는 `backend/app/accounts/deletion.py` 로 추출해 운영자 경로와 공유한다.
- Play Console 「데이터 보안」의 **계정 삭제 URL 칸에 실제로 입력**했다. 그 칸은
  요구사항 3가지를 명시한다 — 앱/개발자 이름 기재, 삭제 요청 단계 표시, 삭제·보관 데이터
  유형과 기간 지정. 만든 페이지가 셋 다 충족한다.
- 구현 중 드러난 더 큰 결함 3건(익명화가 로그인을 안 끊음 / `email_verified` 잔존 /
  평문 PII 잔류)은 저장소 `PROGRESS.md` 모바일 앱 절에 기록.
- 🔴 남은 트레이드오프: `phone_hash` 를 **일부러 남긴다**(1폰=1계정 가드). 비우면
  탈퇴→재가입 무료혜택 루프가 열린다. 대가로 같은 번호 자동 재가입이 막힌다.
