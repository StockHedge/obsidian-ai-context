# 2026-08-01~09 · 캠페인 사이트 단위 전환, 갱신 결제, 코드리뷰 2회

노트북 세션. 캠페인 혜택 구조를 바꾸고, 무료가 끝난 뒤의 회수 경로(갱신 결제)를 만들고,
크레딧이 어디로 갔는지 설명할 수 있게 원장을 넣었다. 마지막에 코드리뷰 2회로 확정 18건 수정.

## 한 일

### 1. 캠페인 무료 호스팅을 **사이트 단위**로 전환 (마이그레이션 `0044`)

"사이트 3개 × 각 3개월". 계정 카운터 하나로는 표현이 **불가능**해서 두 축으로 쪼갰다 —
`User.promo_free_sites`(남은 사이트 수) + `Subscription.free_months_remaining`(그 사이트의
남은 개월). 총 9개월을 계정 단위로 주면 사이트 3개를 굴릴 때 한 달에 3이 빠진다.

소진 순서는 **캠페인 → 레퍼럴**. 캠페인 몫은 사이트를 접으면 함께 사라지는 소멸성 자원이라
먼저 태우는 쪽이 사용자에게 유리하다. 결정 지점을 `payments/free_hosting.py` 한 곳에 모았다.

### 2. 무료 종료 후 회수 경로

`무료 소진 → D-3 안내 SMS(결제 링크) → 만료 → 유예 3일 → 유예 D-2 정지 예고 → 정지`.

링크는 **로그인 없이 바로 결제**(서명 토큰 7일). 문자를 받은 사람에게 로그인을 요구하면
대부분 이탈한다는 판단.

### 3. 연간 구독 — 10개월치 가격(2개월 무료). 신규·갱신 양쪽. **할인율(%) 표기 금지**.

### 4. 파이프라인 계측 (`0045`)

스테이지별 토큰·**실제 응답 모델**·`stop_reason`, 그리고 프롬프트·단가표의 **내용 해시**.
버전 문자열을 손으로 적으면 갱신을 잊는다는 이유로 파일 내용에서 지문을 뽑는다.

### 5. 배포 직전 HTML 게이트

Tier A(빈 HTML·구조 태그 누락·`eval`/`document.write`/`new Function`)는 **차단**,
Tier B(화이트리스트 밖 리소스 호스트·2MB 초과 등)는 **경고 로깅만**.

⚠️ `<a href>` 는 **검사하지 않는다.** 사용자 사이트는 네이버 지도·예약·인스타를 정상적으로
링크한다 — 리소스 로딩과 사용자 이동을 같은 규칙으로 막으면 멀쩡한 사이트가 배포 불가가 된다.
게이트는 `deploy_site`·`restore_site` 두 함수에만 넣어 생성·노코드 편집·AI 수정·정지 해제를
한 번에 덮었다.

### 6. 크레딧 원장 (`0046`)

증감 26개 지점을 `credit_ledger` 에 기록. 사용자는 결제 내역 탭에서 적립/차감을 본다.
`balance_after` 는 **원자 UPDATE 의 `RETURNING`** 에서 가져온다 — 따로 SELECT 하면 그 사이
다른 요청이 끼어들어 실제와 다른 잔액이 남는다. 작업 중 원자성 위반 3곳도 함께 해소.

### 7. 프로모션 크레딧 소멸 (`0048`) — **게이트 OFF**

FIFO(`적립액 − 적립 이후 차감액`, 잔액이 상한) + D-7 안내. 안내가 소멸보다 **반드시 먼저**
나가야 하는데, 이걸 시간 창으로 짜면 게이트를 마감 직전에 켰을 때 안내가 영영 안 나간다.
그래서 **상태**(`promo_expiry_notified_at`)로 인터록을 걸었다.

지금까지 문서·화면이 "적립 후 만료 없음"을 전제로 안내해 왔으므로, **고지를 본 사용자가
생긴 뒤에 켠다**. 관련 서술은 [[표기-주의사항]]·[[확정-결정]]에서 정정 완료.

### 8. 그 밖

운영자 콘솔 모바일 잘림 수정, 결제 내역 크레딧 표시, 포스터 v2([[자산-인벤토리]]),
Creem 활성화 절차 정리, 마케팅 자동화 구현 범위 보고.

## 코드리뷰 2회 — 확정 18건 수정

6차원 병렬 리뷰 30건 → 건별 적대적 검증 → **확정 18 / 기각 12**.
방법과 교훈은 패턴으로 승격했다: [[adversarial-verification-of-review-findings]].

가장 값진 두 건:

- 🔴 **갱신 결제가 100% 실패하고 있었다.** `rate_limit()` 이 내부적으로 `get_current_user`
  에 의존해 비로그인 요청이 핸들러 도달 전에 401. **로그인된 브라우저로 열면 정상으로
  보인다** — 개발자는 늘 로그인 상태이고 문자를 받는 사람은 전원 로그아웃이다.
  회귀 방지를 화면이 아니라 **의존성 트리 구조** 검사로 걸었다(`test_renewal_no_auth.py`).
- 🔴 **연간 정기청구가 `Payment` 에 1/10 로 기록**됐다. 청구는 맞고 기록만 틀려서,
  환불 상한·영수증·매출 집계가 전부 어긋난다. 증상은 첫 연간 구독 **365일 뒤**에 나타난다.

## 되짚을 것

- **"모바일 렌더 확인"을 완료로 보고했다가 정정했다.** 화면이 그려지는 것만 봤고 결제가
  되는지는 보지 않았는데, 실제로는 그 화면의 결제가 전부 401 이었다.
  **렌더 확인은 동작 확인이 아니다.**
- **LLM API 전환 논의에서 내 반박을 철회했다.** "캐싱으로 비용이 준다"고 반박했는데
  실측하니 이 파이프라인은 입력이 작고(S2 시스템 블록 약 11.8K자) **출력이 크다**(HTML 약
  25K 토큰). 상대의 가정이 맞았다. 결정은 실측(`metrics`) 0건이라 **보류**.
- 서브에이전트에 구현을 맡길 때 **"기존 구현 선조사"** 를 지시하지 않으면 중복 사문 코드가
  생긴다(#87 → #89 실제 발생).
