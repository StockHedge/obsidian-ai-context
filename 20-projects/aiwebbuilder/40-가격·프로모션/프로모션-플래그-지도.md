# 프로모션 플래그 지도

**어떤 토글이 무엇을 켜는가.** 이 제품의 프로모션은 플래그 몇 개가 서로 얽혀 있고,
이름만 보고 짐작하면 틀린다. 가격을 건드리기 전에 여기부터 본다.

## 가격표 (정가)

| 항목 | 가격 |
|---|---|
| 배포 1회 | 9,900원 (오픈가 · 정가 14,900) |
| 호스팅 Basic | 3,900원/월 |
| 호스팅 Plus | 7,900원/월 |
| 호스팅 Pro | 14,900원/월 |

할인: 학생 30% / 소상공인·스타트업 20% (인증 후 자동)

## 플래그

**코드 기본값과 운영 실측을 나눠 적는다.** 함정 4 대로 DB 행이 코드 기본값을 이기므로,
기본값만 보고 운영 동작을 짐작하면 틀린다. 운영 열은 2026-08-09 `fly ssh` 직접 조회.

| 키 | 무엇을 하는가 | 코드 기본값 | **운영 실측(08-09)** |
|---|---|---|---|
| `promo_bundle_enabled` | 호스팅 첫 달 **−4,000원**(0 floor) | True | **false** (07-31 폐기) |
| `promo_bundle_until` | **위 할인과 아래 0원 행사의 공통 종료일** | 2026-12-31 | — |
| `promo_first_month_free` | 호스팅 첫 달 **전 티어 0원** | False | false |
| `free_deploy_promo_enabled` | 첫 배포 0원 (날짜 조건 없음) | False | **true** |
| `lifecycle_messaging_enabled` | 미배포 이탈자 복귀 메일 | — | true |
| `nocode_edit_enabled` | 노코드 직접 편집 노출 | — | true |
| `promo_modal_enabled` | 캠페인 인터스티셜 팝업 | True | (DB 행 없음 → true) |
| `overseas_payment_enabled` | Creem 해외 결제 | False | false (심사 대기, 의도) |
| 🆕 `promo_credit_expiry_enabled` | 프로모션 크레딧 **소멸** | False | **false** |
| 🆕 `marketing_sequences_enabled` | 온보딩·업셀 시퀀스 | False | **false** |

### 🆕 신규 2종을 켜기 전에

- **`promo_credit_expiry_enabled`** — 지금까지 문서·화면이 "적립 후 만료 없음"을 전제로
  안내해 왔다. **그 고지를 본 사용자가 생긴 뒤** 켠다. 인터록이 있어 켜더라도 D-7 안내가
  먼저 나가고 그 뒤에 소멸하므로 즉시 소멸은 일어나지 않는다([[확정-결정]] §1).
- **`marketing_sequences_enabled`** — `sequences.py` 는 **테스트가 0건**이라
  **켜는 순간이 그 코드의 첫 실행**이 된다. 발송 대상이 실사용자이므로, 켜기 전에
  dry-run 으로 대상 수부터 확인할 것.

## 🔴 함정 1 — `promo_bundle_until` 은 두 행사를 겸한다

이름은 "번들" 기한인데, `promo_first_month_free`(첫 달 전 티어 0원)의 종료일도 이 값을 쓴다
(`pricing.py:270-277`). 즉 **번들을 연장하려고 날짜를 늘리면 첫 달 0원까지 딸려 연장된다.**

2026-07-31 에 8/31 → 12/31 로 늘리면서, 첫 달 0원이 4개월 더 연장되는 것을 막기 위해
`promo_first_month_free` 를 OFF 로 내리기로 결정했다.

## 🔴 함정 2 — 번들 킬스위치는 0원 킬스위치가 아니다

`promo_bundle_enabled` 를 꺼도, `promo_first_month_free` 가 켜져 있으면
**첫 달은 여전히 0원**이다. 판정 순서가 free-month 가 먼저이고 거기서 이미 0 을 반환한다
(`pricing.py:270-277` → `279`). "번들 프로모션 활성" 을 끄면 다 꺼진다고 믿으면 안 된다.

## 🔴 함정 3 — 첫 달 0원으로 가는 경로가 셋이다

1. `promo_first_month_free` = True → 전 티어 0원
2. 번들 −4,000원 → **Basic 만** 0원 (3,900 − 4,000 → floor 0). Plus 3,900 / Pro 10,900
3. **운영자 레퍼럴 perk** (`payments.py:840`, `User.hosting_free_months > 0`) →
   위 두 플래그를 **전부 우회**해 0원. START2026 수령자도 여기 해당한다.

"왜 0원이 나가나" 를 진단할 때 3번을 빠뜨리기 쉽다.

## 🔴 함정 4 — 코드 기본값을 고쳐도 반영되지 않을 수 있다

`app_settings` 는 **DB 행이 코드 기본값을 무조건 이긴다**(`app_settings.py:110-112`).
`POLICY_DEFAULTS` 를 수정하고 배포해도, 운영자가 콘솔에서 그 키를 한 번이라도 저장했다면
DB 행이 남아 있어 조용히 무시된다.

- 확인: `GET /api/admin/policy` 의 `effective.*` 와 `defaults.*` 비교
- 변경: 운영자 콘솔 **정책 탭 → "번들 프로모션 (KP-2 적용)" 그룹**
- ⚠️ 콘솔 안내문 "기본값으로 입력하면 코드 기본값 복귀" 는 **거짓**이다.
  `set_many` 에 삭제 분기가 없어 그 값으로 행이 남는다.

## 🔴 실사례 — 2026-07-31 "2026-09-31" 사고

위 함정들이 이론이 아니라는 증거. 어느 시점에 콘솔에서 `promo_bundle_until` 에
**`2026-09-31`**(존재하지 않는 날짜)이 저장됐고, 그대로 운영에서 돌고 있었다.

두 소비 지점이 같은 `ValueError` 를 **다르게 삼켰다**:

| 파일 | 예외 처리 | 결과 |
|---|---|---|
| `pricing.py:283` | `except ValueError: return recurring` | 할인 **미적용** → 정가 청구 |
| `payments.py:799` | `except ValueError: pass` | `promo_active` **True 유지** → 배지 표시 |

즉 **화면엔 "첫 달 0원", 청구는 정가**. 상단 이벤트 바가 거짓말을 하고 있었다.
결제 분쟁으로 직결되는 상태였고, 아무도 에러 로그를 보지 못했다 — 예외가 조용히 삼켜졌기 때문이다.

발견 경위: 만료일을 바꾸려 현재값을 **조회**하다 눈에 띄었다. 바꾸기 전에 읽지 않았다면
그대로 지나갔을 것이다. → **변경 전 현재값 조회를 습관화할 것.**

재발 방지: `admin_cli.py` 의 `_DATE_KEYS` 가 `date.fromisoformat` 으로 검증해
저장 전에 거부한다. 다만 **운영자 콘솔에는 아직 이 검증이 없다** — 콘솔에서 직접
입력할 때는 여전히 사람이 확인해야 한다(후속 과제).

## 운영 명령 (CLI)

콘솔에 UI 가 없는 것(캠페인 코드 등)은 `admin_cli` 로 처리한다.
`fly ssh` 는 상시 실행 머신에 붙는 것이라 **추가 요금이 없다**.

```bash
# 조회
fly ssh console -a aiwebbuilder-api \
  -C "sh -c 'cd /app && PYTHONPATH=/app python scripts/admin_cli.py promo'"
fly ssh console -a aiwebbuilder-api \
  -C "sh -c 'cd /app && PYTHONPATH=/app python scripts/admin_cli.py set-policy'"

# 변경 (금액·결제·혜택 키는 --force 필수, 없으면 diff 만 보여주고 멈춘다)
... admin_cli.py promo START2026 --expires-kst 2026-10-31 --force
... admin_cli.py promo START2026 --active false --force      # 캠페인 즉시 중단
```

⚠️ `cd /app` + `PYTHONPATH=/app` 을 **함께** 줘야 한다. 절대경로로만 부르면
`ModuleNotFoundError: No module named 'app'`.

**어디서 바꿀 것인가**
- `promo` 계열 → **CLI**. 콘솔에 UI 가 없고, API 가 매 요청마다 DB 를 읽어 즉시 반영.
- 정책 → **콘솔**. CLI 는 호출 프로세스 캐시만 갱신해 `fly apps restart` 가 필요하고,
  머신이 1대라 재시작 = 수십 초 단절이다.

## 시간대

`pricing.py` 는 `date.today()` 를 쓰고 컨테이너 TZ 는 **UTC** 다(fly.toml·Dockerfile 에 TZ 미설정).
따라서 `promo_bundle_until = 2026-12-31` 은 KST 기준 **2027-01-01 09:00** 까지 유효하다.
반면 [[START2026]] 의 만료는 KST 기준으로 끊었다 — 두 기준이 다르다는 것만 인지할 것.
