## 1. START2026 캠페인 (2026-07-31 확정)

| 항목 | 확정값 |
|---|---|
| 한도 | **선착순 999명** (1인 1회) |
| 마감 | **2026-09-30** |
| 크레딧 | 15,000 (용도 구분 없는 단일 잔액) |
| 무료 호스팅 | **사이트 3개 × 각 3개월** = 총 9개월 |
| 무료 호스팅 플랜 | **Plus 고정** |
| 적용 조건 | **프로모션 기한 내에 사이트를 생성**해야 한다 |

### 왜 "사이트당"인가

총 9개월을 계정 카운터 하나로 주면 사이트를 3개 굴릴 때 **한 달에 3이 빠진다**(3개월 만에
소진). "사이트 3개를 각각 3개월"이라는 약속을 지키려면 개월 수를 **구독=사이트 단위**로
세야 한다. 그래서 두 축으로 쪼갰다:

- `User.promo_free_sites` — 무료 구독을 더 붙일 수 있는 **남은 사이트 수**
- `Subscription.free_months_remaining` — 그 사이트의 **남은 개월**

기존 `User.hosting_free_months`(운영자 레퍼럴)는 계정 단위 그대로 두고 **병존**한다.
소진 순서는 **캠페인 → 레퍼럴**이다(캠페인은 사이트를 접으면 함께 사라지는 소멸성 자원이라
먼저 태우는 쪽이 사용자에게 유리).

### 만료의 의미가 항목마다 다르다 — 광고 문구 주의

- **크레딧**: 🔴 **2026-08-01 정책 변경** — 마감일까지 미사용분은 **소멸**한다.
  (그 전까지는 만료가 없었다. 이 문장을 근거로 쓴 옛 안내가 남아 있다면 전부 정정 대상이다.)
  구현 완료·게이트 `promo_credit_expiry_enabled` **기본 OFF** — 고지가 충분히 노출된 뒤 켠다.
- **무료 호스팅**: `User.promo_free_hosting_until` 이후에 배포한 사이트에는 **안 붙는다**.
  코드를 등록만 해두고 11월에 만든 사이트는 대상이 아니다.

→ "적립 후에는 기한이 없어요"는 크레딧에만 참이다. 호스팅에 대고 쓰면 허위 표기가 된다.
자세한 건 [[표기-주의사항]].

### 무료 종료 후 타임라인

```
무료 소진 → [D-3 갱신 안내 SMS + 결제 링크] → 만료
  → 유예 3일 (사이트 살아 있음) → [유예 D-2 정지 예고 SMS] → 사이트 정지
```

결제 링크는 **로그인 없이 바로 결제**되며 유효기간 **7일**(서명 토큰).
로그인을 요구하면 문자를 받은 사람 대부분이 이탈한다는 판단.

| 플랜 | 월간 | 연간 |

| Basic | 3,900 | **39,000** |

## 4. 반복해서 데인 함정

### 실재하지 않는 날짜 → 무음 실패 (2026-07-31 실제 사고)

`promo_bundle_until` 에 **`2026-09-31`** 이 들어가 있었다. 9월은 30일까지다.

두 곳의 `except ValueError` 가 서로 다르게 처리해서, **화면은 "첫 달 0원"인데 실제로는
정가가 청구**됐다. 에러 로그도 없었다. 지금은 `app_settings` 쓰기 지점에서 날짜를 파싱해
막고, 콘솔 UI 는 `<input type="date">` 라 구조적으로 입력이 불가능하다.

교훈: **값을 바꾸기 전에 현재 값을 읽는다.** 이 버그는 그렇게 해서 발견됐다.

### 만료 시각은 naive UTC 로 저장된다

KST 로 끊으려면 `+09:00` 오프셋을 붙인다. 벽시계(`23:59:59`)를 그대로 넣으면 실제 만료가
**9시간 늦어진다**. `admin_cli.py promo --expires-kst` 는 이 변환을 알아서 한다.

### 광고 문구와 코드가 갈라진 전례가 반복된다

티어 표기, 만료 개념, 기한 하드코딩 — 세 번 다 코드를 확인하지 않고 문구를 먼저 냈다.
금전 혜택이라 분쟁 소지가 실질적이다. [[표기-주의사항]] 을 광고 전에 반드시 본다.

## 6. 운영 반영 현황 (2026-07-31 실측)

### ✅ 백엔드는 배포됐다

마이그레이션 `0044`(캠페인 무료 호스팅)·`0045`(계측) 적용 완료, health 200.
운영 API 응답으로 확인한 값:

```json
{"credits":15000,"free_hosting_months":9,"free_hosting_sites":3,
 "free_hosting_months_per_site":3,"remaining_uses":999,
 "expires_at":"2026-09-30T14:59:59Z"}
```

`14:59:59Z` = KST 23:59:59. 총 9개월이 API 경계에서 곱해져 나온다(배너·팝업이 각자
곱하면 한 곳이 빠졌을 때 값이 갈리므로 서버가 정규화한다).

### 🔴 프론트는 아직 구버전이다

운영 번들에 `계속 이용하시겠어요`(갱신 결제 화면), `billing_yearly`(연간 토글)가
**0건**이다. **PR #112 머지 대기 중** — 머지하면 GitHub Actions가 Pages에 배포한다.

당장 깨지진 않는다(구버전은 `cycle`을 안 보내고 백엔드가 monthly 로 처리). 다만 무료
구독이 만료되기 시작하면 문자 링크가 갈 곳이 없다.

### 파이프라인 계측이 켜졌다

`pipeline_runs.metrics`(JSONB)에 스테이지별 토큰·실제 응답 모델·`stop_reason` +
프롬프트/단가표 **내용 해시**가 남는다. "비용이 높으면 그때 최적화한다"가 성립하려면
근거가 쌓여 있어야 하고, 이 값들은 소급 복원이 불가능하다.

⚠️ 운영 `pipeline_runs`는 **현재 0건**이다(2026-06-21 DB 초기화 사고 이후 생성 없음).
계측 데이터는 다음 실제 생성부터 쌓인다.

### 운영 플래그 실측 (DB 10건)

| 플래그 | 값 | 비고 |
|---|---|---|
| `free_deploy_promo_enabled` | **true** | 첫 배포 무료 정상 동작 |
| `overseas_payment_enabled` | **false** | Creem — 심사 전 노출 방지, **의도된 OFF** |
| `promo_bundle_enabled` | **false** | 이번에 폐기 |
| `nocode_edit_enabled` | true | |
| `lifecycle_messaging_enabled` | true | |

> 존재하지 않는 키를 조회하면 `None`이 나온다. `launch_free_deploy_enabled`는 **없는
