# 표기 주의사항

광고 문구와 실제 코드가 갈라진 사례를 모은다. **금전 혜택을 다루므로 분쟁 소지가 실질적**이고,
"그럴 것 같다" 로 쓴 문구가 실제로 여러 번 틀렸다.

원칙: **코드가 실제로 무엇을 하는지 확인하지 않은 문구는 내지 않는다.**

## 1. "Plus 3개월 무료" 라고 단정하지 말 것

호스팅 무료 개월(`User.hosting_free_months`)은 **사용자가 고른 플랜에 그대로 적용**된다.
코드 어디에도 티어 상한이 없다(`promo_code.py:11`, `payments.py:840-843`, `jobs.py:130-134`).

> 🔴 **2026-07-31 에 구조가 바뀌었다.** 아래는 그 이후 기준이다. 이전 판("티어 무관 ·
> 3개월")으로 쓰인 문구가 남아 있으면 전부 정정 대상이다.

- ❌ "호스팅 3개월 무료" — **총 9개월**이다(사이트 3개 × 각 3개월)
- ❌ "어느 플랜이든 무료" — 이제 **Plus 고정**이다. 사용자가 고르지 않는다
- ❌ "티어 무관" — 옛 구조. 지금은 배포 시 Plus 무료 구독이 자동으로 붙는다
- ✅ "호스팅 9개월 무료 — 사이트 3개에 각각 3개월, Plus 플랜으로"

포스터 v2 는 이 표기로 갱신됐다(v1 은 "3개월 · Plus까지"로 낡았으니 쓰지 말 것).
사이트마다 3개월씩 **따로** 소진되므로 "한 사이트를 9개월"이 아니다.

## 2. 🔴 적립 혜택의 만료 — **2026-08-01 에 정책이 뒤집혔다**

> 이 절은 원래 "적립된 혜택에는 만료가 없다"였다. 그 서술을 근거로 만든 옛 안내가
> 남아 있을 수 있으니, 캠페인 문구를 손댈 때 **여기부터 확인**한다.

### 크레딧 — 이제 소멸한다 (단, 게이트 OFF)

마감일까지 쓰지 않은 **프로모션 적립분**은 소멸한다. 구현·FIFO 계산·D-7 안내가 모두
들어갔고 게이트 `promo_credit_expiry_enabled` 는 **기본 OFF** — 고지가 충분히 노출된 뒤 켠다.

소멸량은 `적립액 − 적립 이후 차감 총액`, 현재 잔액이 상한이다.
15,000 받고 5,000 을 썼으면 **10,000 이 소멸 대상**이다(전액이 아니다).

- ✅ "받은 크레딧은 9월 30일까지 사용해 주세요"
- ❌ "크레딧은 기한 없이 쓸 수 있어요" — **이제 거짓**
- ⚠️ 소멸 대상은 **프로모션 적립분뿐**이다. 가입 보너스·결제 보너스는 남는다.
  "크레딧이 전부 사라진다"고 쓰면 과장이다.

### 호스팅 무료 — 기한의 의미가 다르다

`User.promo_free_hosting_until` **이후에 배포한 사이트에는 붙지 않는다.** 코드만 등록해
두고 캠페인이 끝난 뒤 만든 사이트는 대상이 아니다("기한 내 **생성**" 조건).

- ✅ "기한 안에 사이트를 만드셔야 무료 호스팅이 붙어요"
- ❌ "코드만 등록해두면 언제 만들어도 돼요" — 거짓

### 왜 이 절이 위험한가

없는 만료를 있다고 하면 표시광고 불일치이고, 있는 만료를 없다고 하면 10월에
"내 크레딧 왜 사라졌나요" CS 가 온다. **양방향 모두 사고**다.

## 3. 크레딧은 용도 구분이 없는 단일 잔액

서버는 `credits: 15000` 이라는 숫자 하나만 적립한다.
"생성 5회 + 노코드 편집 1만원" 은 **기획상의 분해**일 뿐 시스템이 강제하지 않는다.

- ❌ 칩 3개로 쪼개 "생성 5회 / 편집 1만원 / 호스팅 3개월" 을 확정처럼 표시
- ✅ 총액 + 쓰임새 — "크레딧 15,000 · 사이트 생성·노코드 편집에 쓸 수 있어요"
- ✅ 분해가 필요하면 "**상당**" 을 붙인다 — "생성 5회 + 편집 1만원 상당"

## 4. 기한 문구가 화면에 하드코딩돼 있다

`Landing.tsx:705`·`Preview.tsx:822` 의 기한 문구는 **게이트 없이 항상 렌더**된다.
날짜가 지나도 그대로 표시되고, API 값(`promo_active`)과 정면 충돌한다.

2026-07-31 에 8/31 → 12/31 로 미뤘을 뿐이라 **2027-01-01 부터 같은 문제가 재발**한다.
근본 처방은 이미 API 가 내려주는 `promo_until` 을 쓰는 것
(`Checkout.tsx:56`·`Dashboard.tsx:1162` 에 필드로 존재하나 화면에 안 그린다).

i18n 은 5개 로케일(ko/en/es/zh/hi) 동시 수정이 규칙이라, 문구 하나에 10곳을 고쳐야 한다.

## 5. 날짜 자체를 확인할 것 — 🔴 실제로 사고가 났다

2026-07-31 에 "9월 31일까지" 라는 지시가 있었다. **9월은 30일까지다.**
인쇄물과 DB 양쪽에 들어가는 값이라 되돌리기 비싸다.

그리고 같은 날, **이미 운영 DB 에 `2026-09-31` 이 들어가 있는 것을 발견했다.**
`pricing.py` 는 파싱 실패를 삼켜 할인을 껐고, `payments.py` 는 같은 예외를 삼키며
배지를 켜둔 채였다 → **화면엔 "첫 달 0원", 청구는 정가.** 상세는
[[프로모션-플래그-지도]] 의 "실사례" 절.

교훈 두 가지:
- 없는 날짜는 에러로 터지지 않고 **조용히 다른 동작**을 만든다. 검증은 입력 시점에.
- **바꾸기 전에 현재값을 읽어라.** 이 사고는 만료일을 바꾸려 조회하다 우연히 발견됐다.
