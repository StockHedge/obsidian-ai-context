# START2026

링크 배포용 프로모션 코드 캠페인. 인스타·카톡·당근에 포스터를 뿌리고, 링크로 들어와
가입하면 혜택이 자동 적립된다.

## 링크

```
https://app.aiwebbuilder.kr/?promo=START2026
```

포스터 QR 도 이 주소를 그대로 인코딩했다(오류정정 level M, 벡터).

## 혜택

| 항목 | 값 | 실제 저장 위치 |
|---|---|---|
| 크레딧 | 15,000 | `User.preview_credits` |
| 무료 호스팅 | **사이트 3개 × 각 3개월** (총 9개월) | `User.promo_free_sites` + `Subscription.free_months_remaining` |
| 무료 호스팅 플랜 | **Plus 고정** | 배포 시 무료 구독 자동 생성 |
| 적용 조건 | **기한 내 사이트 생성** | `User.promo_free_hosting_until` |

⚠️ 2026-07-31 에 구조가 **바뀌었다**. 이전에는 `User.hosting_free_months`(계정 단위)에
넣었는데, 그러면 사이트를 3개 굴릴 때 한 달에 3이 빠져 "각각 3개월"을 표현할 수 없다.
지금은 남은 **사이트 수**와 사이트별 **남은 개월**을 따로 센다. 상세는 [[확정-결정]].

**크레딧은 용도 구분이 없는 단일 잔액이다.** "생성 5회(5,000) + 노코드 편집(10,000)" 은
기획상의 설명일 뿐, 서버는 15,000 이라는 숫자 하나만 적립한다. 생성에 다 써도 되고
편집에 다 써도 된다 → 광고에서 쪼개 단정하지 말 것([[표기-주의사항]]).

## 조건

- 한도 **999회** · **1인 1회**(`User.promo_code_used` 로 판정) — 2026-07-31 에 500 → 999
- 만료 **2026-09-30** (2026-07-31 에 12-31 → 9-30 으로 앞당김)
- 🔴 **만료의 의미가 혜택마다 다르다.**
  - **크레딧**: 🔴 **2026-08-01 변경 — 마감일까지 미사용분은 소멸한다.**
    소멸량은 FIFO(`적립액 − 적립 이후 차감액`, 잔액이 상한). 게이트 기본 OFF.
  - **무료 호스팅**: `promo_free_hosting_until` 이후 배포한 사이트에는 **안 붙는다**.
    코드만 등록해두고 11월에 만든 사이트는 대상이 아니다.
  → "적립 후 기한 없음"은 **크레딧에만** 참이다. 호스팅에 대고 쓰면 허위 표기가 된다.

## 운영 명령

```bash
# 현황
GET /api/promo/admin/list

# 즉시 중단
PATCH /api/promo/admin/START2026?is_active=false

# 만료일 변경 (2026-07-31 신설)
PATCH /api/promo/admin/START2026?expires_at=2026-09-30T23:59:59%2B09:00
```

⚠️ 만료 시각은 **naive UTC** 로 저장된다. KST 로 끊으려면 위처럼 `+09:00` 오프셋을 붙일 것 —
벽시계(`23:59:59`)를 그대로 넣으면 실제 만료가 **9시간 늦어진다**(KST 10/1 08:59:59).
회귀 테스트가 `backend/tests/test_promo_codes.py` 에 고정돼 있다.

**더 쉬운 방법 — CLI** (토큰 불필요, 만료를 KST 로 받아 알아서 변환한다):

```bash
fly ssh console -a aiwebbuilder-api \
  -C "sh -c 'cd /app && PYTHONPATH=/app python scripts/admin_cli.py promo START2026'"

# 변경 (--force 없으면 diff 만 보여주고 멈춘다)
... admin_cli.py promo START2026 --expires-kst 2026-10-31 --force
... admin_cli.py promo START2026 --active false --force
```

조회하면 `expires_at (KST)` 가 함께 나온다. 실제로 이 표시 덕분에 기존 만료가
"12/31까지" 가 아니라 **2027-01-01 08:59:59 KST** 였다는 걸 발견했다. 상세는
[[프로모션-플래그-지도]] 의 "운영 명령" 절.

## 링크 진입 시 화면

2026-07-31 구현 완료. `Landing.tsx` 가 `?promo=` 를 잡은 뒤 `GET /api/promo/{code}` 로
조회해 히어로 위에 혜택 카드를 띄운다. 만료·오타 코드는 "종료된 캠페인" 을 대신 보여준다.

그 전까지는 **무음 실패**였다 — 코드를 sessionStorage 에 담고 URL 에서 지우기만 해서,
포스터를 보고 들어온 사람이 화면에서 아무 혜택도 못 보고 가입을 마쳤다. 만료 후에는
에러조차 없이 혜택 0 으로 끝나 결제 화면에서야 이상을 눈치채는 구조였다.

## 캠페인 팝업

랜딩 진입 0.8초 뒤에 뜨는 인터스티셜(카페24 류). **캠페인을 모르고 들어온 방문자**용이라,
`?promo=` 링크로 온 사람에겐 띄우지 않는다 — 히어로 위 혜택 카드를 이미 보고 있어 중복이다.

레이아웃 3단: **히어로**(코드 스탬프 + 혜택 칩 + CTA) → **오렌지 정보 스트립**(선착순·기한)
→ **"7일 동안 보지 않기"**. 포스터와 같은 어휘(딥블루 + 오렌지 + 대시 테두리 코드 칩)라
캠페인 전체가 하나로 읽힌다.

- 설정은 `frontend/src/lib/promoCampaigns.ts` 한 곳. 다음 캠페인은 **항목 하나 + i18n
  5로케일 키**만 추가하면 되고 컴포넌트는 건드리지 않는다.
- ⚠️ 캠페인이 바뀌면 **`id` 를 새로 줄 것**. 재사용하면 이전에 "안 보기" 를 누른 사람에게
  새 캠페인도 안 보인다.
- ✅ **콘솔에서 즉시 끌 수 있다** — 정책 탭 *"출시 행사 · 기능 게이트"* 의
  `promo_modal_enabled`(기본 True). 게이트는 두 겹: 캠페인 존재 여부는 코드
  (`promoCampaigns.active`), 긴급 중단은 이 플래그(콘솔).
  조회 실패 시엔 뜨지 않는다 — 네트워크 오류로 광고가 뜨는 것보다 안전하다.
- CTA 를 누르면 `pending_promo` 를 심고 `/new` 로 보낸다 — 링크 없이 팝업만 봐도 혜택이 붙는다.

## 무료 종료 후 타임라인

```
무료 소진 → [D-3 갱신 안내 SMS + 결제 링크] → 만료
  → 유예 3일 (사이트 살아 있음) → [유예 D-2 정지 예고 SMS] → 사이트 정지
```

문자에 담기는 링크는 **그 사이트의 호스팅 갱신 결제 화면**으로 바로 간다.
**로그인을 요구하지 않으며** 유효기간은 7일(서명 토큰) — 로그인을 끼우면 문자를 받은
사람 대부분이 이탈한다는 판단.
