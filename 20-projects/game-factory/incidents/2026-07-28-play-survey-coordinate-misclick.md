# Play Console 설문 — 좌표 클릭이 데이터 보안 최상위 문항을 "수집 안 함"으로 바꿨다

## 증상

alchemy의 데이터 보안 설문을 브라우저 자동화로 진행하던 중, 화면에서 찾은 라디오를
"계정 로그인 여부 = 아니요"로 판단하고 클릭했다. 실제로 클릭된 것은 **최상위 문항**
"앱에서 필수 사용자 데이터 유형을 수집하거나 공유하나요?"의 **아니요**였다.

결과: AdMob(광고 ID 수집)을 쓰는 앱이 **"데이터를 수집하지 않음"**으로 선언될 뻔했다.
Google에 그대로 제출됐다면 [[2026-07-22-adid-declaration-submit-block|AD_ID 선언 하드블록]] 계열이
아니라 **허위 선언에 의한 정책 위반**이 된다. 앱 삭제와 계정 경고 사유다.

직후 스크린샷 검증에서 발견해 "예"로 복구했다. 그 뒤 모든 클릭을 스크린샷으로
1건씩 확인하며 진행했다.

같은 설문에서 **이전에 입력된 오류도 발견**했다 — "계정 생성 방법"에 `기타`가 체크되고
설명란에 `기기 또는 기타 ID(광고 ID)`가 적혀 있었다. 데이터 *유형*을 계정 *생성 방법*
칸에 넣은 것이다. 이번 세션의 클릭이 아니었고, 폼 상태를 검증 없이 물려받으면
이런 오염이 그대로 제출된다. 해제 후 "계정을 만들도록 허용하지 않음"으로 바로잡았다.

카테고리 드롭다운은 ref 클릭·좌표·타이핑·스크롤바 드래그를 모두 시도했으나 끝내
자동화되지 않아 사람이 처리했다.

## 근본원인

**Play Console 설문 페이지가 Flutter 캔버스로 렌더된다.** DOM에 의미 있는 접근성 트리가
없어 `find`가 돌려주는 요소 식별이 시각적 추정에 기댄다. 라디오가 화면상 비슷한 위치에
반복 배치되므로, 문항이 아니라 **좌표가 같으면 같은 요소로 보인다.**

기존에도 같은 결함이 기록돼 있었다 — `tools/console-register.mjs` 주석에 "좌표 클릭 금지"가
명시돼 있고, 언어 드롭다운에서 좌표 클릭이 일본어·핀란드어를 연속 오선택한 전례가 있다.
**이번 사고는 새 발견이 아니라 이미 아는 함정을 무시한 결과다.**

더 근본적으로: 설문에는 **"쓰기 후 확인"이 없었다.** 클릭 → 다음 클릭으로 진행하면서
직전 클릭이 무엇을 바꿨는지 검증하는 단계가 파이프라인 어디에도 없다.

## 수정

절차 수정만 가능하다(코드 없음 — Google이 API를 주지 않는다).

- 오선택 복구: 최상위 문항 "예"로 원복, 이후 전 문항 스크린샷 대조.
- 기존 오염 정정: 계정 생성 방법 `기타 + 광고 ID` → "계정을 만들도록 허용하지 않음".
- `docs/ai/NOW.md`에 함정으로 등재 — "설문 페이지는 클릭마다 스크린샷 검증 필수".

## 재발방지

- **Flutter 캔버스 페이지에서 좌표·시각 추정 클릭 후에는 반드시 스크린샷으로 결과를
  확인한다.** 클릭 성공 로그는 "무엇이 바뀌었는가"를 말해주지 않는다.
- **정책 선언 문항(수집/공유, 광고 ID, 데이터 유형)은 되돌릴 수 있는 UI 조작이 아니라
  법적 선언이다.** 다른 폼 필드와 같은 신뢰도로 다루지 않는다. 제출 직전 전 문항을
  `store-assets/console-survey.md`의 산출 답안과 1:1 대조한다.
- **물려받은 폼 상태를 검증 없이 신뢰하지 않는다.** 이전 세션·사람이 입력한 값도
  틀릴 수 있고, 제출 책임은 마지막에 누른 쪽이 진다.
- 이미 기록된 함정(`console-register.mjs`의 "좌표 클릭 금지")을 무시하지 않는다.
  같은 도구를 다시 쓸 때 주석을 먼저 읽는다.
