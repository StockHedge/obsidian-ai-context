# AGY — 작업을 마친 세션이 42분간 유휴로 큐를 점유하다 타임아웃 실패로 판정

## 증상

`color-gate(AGY)`의 dev 잡 `9c53e3d530cf`(2026-07-25 18:14:22 시작):

- 18:17:11 — 작업을 마치고 커밋 `507140d` 생성 (**실작업 약 3분**)
- 18:19~18:59 — `[heartbeat] N분 경과 — 최근 2분 변경 파일 0개`를 **44회 반복**
- 18:59:29 — `Error: timeout waiting for response`로 종료, 잡 **실패** 판정

즉 3분 일하고 **42분을 유휴로 태웠다.** 단일 직렬 큐라 그동안 다른 잡은 전부 대기했다.
그리고 실패 판정이었기 때문에(당시엔 dev 실패 시 상태 전이가 없어서)
[[2026-07-27-pipeline-dev-failure-orphan]]의 고아 상태로 이어졌다.

AGY 레인 총 잡 시간 204.5분 중 이 한 건이 45.1분(22.1%)이다.

## 근본원인

두 계층이 동시에 비어 있었다.

1. **하트비트가 관측만 하고 개입하지 않았다.** `AgyProvider._heartbeat`는 무변화를
   `quiet_minutes`로 세면서도 그 값을 잔류 프로세스 정리(`_sweep_strays`)에만 썼다.
   아무리 오래 멈춰 있어도 세션 자체를 끝내지 않는다. 애초에 `_heartbeat`는 `proc`
   핸들을 받지 않아 **종료시킬 수단이 없었다.**
2. **유일한 상한이 agy CLI의 `--print-timeout 45m`이었다.** 파이썬 측에는 잡 벽시계
   한도가 전혀 없었고(2026-07-27 `JOB_TIMEOUT_S`로 백스톱 추가), 45m는 `.env`에 명시도
   없는 코드 기본값이었다. 즉 "45분"은 의도된 값이 아니라 방치된 기본값이며, 그것이
   사고의 직접 파라미터였다.

왜 agy 프로세스가 안 죽었는지는 CLI 내부라 확정 불가다. print 모드가 최종 보고를 낸 뒤
종료 시퀀스에서 멈추는 것으로 보이며, 같은 세션에서 `[cleanup] bare-agy` 좀비도 관측된다.

## 수정 (2026-07-28)

`factory/runner.py` — 유휴 조기 종료를 하트비트에 부여했다.

- `_heartbeat`가 `proc`과 `idle_state`를 받는다. 무변화가 `FACTORY_AGY_IDLE_STOP_MIN`
  (기본 12분) 연속되면 프로세스를 종료한다.
- **작업 완료 여부를 git 으로 판정한다.** 스폰 직전 HEAD를 기록해 두고, 유휴 종료 시점에
  HEAD가 바뀌었으면 "작업을 마치고 프로세스만 안 죽은 것"으로 보고 **성공**으로 마감한다.
  바뀌지 않았으면 실패로 마감해 재시도/에스컬레이션 정책에 넘긴다.
  이 판정이 있어야 color-gate 케이스가 정확히 구제된다 — 결과물은 멀쩡했다.
- `print_timeout` 기본값을 45m → 30m로 낮추고 `.env`에 명시했다. 유휴 종료(12분)가
  먼저 걸리므로 print-timeout은 진짜 백스톱 역할만 한다.

## 재발방지

- 하트비트처럼 "관측하는 코드"를 새로 만들 때는 **관측값에 반응하는 경로를 같은 커밋에서
  함께 넣는다.** 지표만 찍고 아무도 읽지 않는 계측은 사고를 기록만 하고 막지 못한다.
- 외부 CLI의 기본값에 의존하지 않는다. 사고 파라미터가 될 수 있는 값(`print_timeout`,
  모델, 폴백)은 `.env`에 명시해 의도를 드러낸다.
- 세션 성패 판정을 **프로세스 종료 코드에만 의존하지 않는다.** git 산출물처럼 독립적인
  증거를 함께 본다.
