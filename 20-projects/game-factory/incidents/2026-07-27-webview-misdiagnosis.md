# 오진 — "WebView 전용 결함 3종"은 실기에서 2건 미재현·1건 원인상이

## 증상

2026-07-24 핸드오프와 세션 메모리에 crowd-clash(AGY)의 베타 실패 원인이
**"WebView 전용 결함 3종"**으로 기록됐고, 다음 세션의 1순위 액션이
`adb logcat으로 WebView JS 크래시 특정`으로 지정됐다.

기록된 3종:
- (a) 메인화면 입력 무반응
- (b) Retry 버튼이 외부 Chrome으로 이탈
- (c) i18n 플레이스홀더 `{n}` 미치환

## 근본원인

2026-07-27 실기 검증(에뮬레이터 API 36 + `adb logcat` + 스크린샷 8장) 결과, **세 항목 모두
기록이 부정확**했다.

| 기록된 결함 | 실측 결과 |
|---|---|
| (a) 입력 무반응 | **오진.** 입력은 정상 동작 — 드래그를 넣으면 조준·발사되고 `VICTORY!`까지 완주한다. 진짜 원인은 타이틀 화면 도달 불가 + 방치 시 10초 자동 패배([[2026-07-27-crowd-clash-title-phase-unreachable]]) |
| (b) Retry 외부 이탈 | **미재현.** RETRY 탭 후 `topResumedActivity`가 `kr.stockhedge.crowdclash/.MainActivity`로 유지됐고 게임이 앱 내부에서 재시작됐다. 외부 인텐트 로그 없음 |
| (c) `{n}` 미치환 | **미재현.** `uiSystem.js:269`가 `t('earnedCoins', { n: state.earnedCoins })`로 params를 정상 전달하며, 실기 화면에 `Earned Coins: +138`로 치환돼 표시됐다 |

또한 **"WebView JS 크래시" 자체가 존재하지 않았다.** logcat에서 모든 ES 모듈이
`https://localhost/src/...`로 정상 로드됐고 `AndroidRuntime`/`Uncaught` 예외가 0건이다.

오진이 발생한 경로는 다음과 같이 추정된다. 베타테스터가 관측한 **증상 서술**(화면이 반응하지
않는 것처럼 보임)이 중간 검증 없이 **근본원인 진술**("WebView 전용 결함")로 승격됐고,
그 상태로 핸드오프 문서와 세션 메모리에 정본으로 굳었다. 이후 세션은 이 전제를 의심하지 않고
`logcat으로 크래시 특정`이라는, 존재하지 않는 대상을 찾는 작업을 1순위로 배정했다.

## 수정

수정 대상은 코드가 아니라 기록이다.

- 세션 메모리 `factory-status-2026-07-23`과 `game-factory/agy/HANDOFF-2026-07-24.md`의
  "WebView 전용 결함 3종" 서술을 실측 결과로 정정한다.
- crowd-clash의 실제 수정 지시는 [[2026-07-27-crowd-clash-title-phase-unreachable]]과
  [[2026-07-27-crowd-clash-globalalpha-leak]]을 근거로 재작성한다.

만약 정정 없이 기존 진단대로 AGY에 수정을 지시했다면, 멀쩡한 입력 코드와 i18n을 건드리고
진짜 원인(부팅 시 phase 덮어쓰기)은 그대로 남았을 것이다. **오진 상태의 수정 지시가 가장 비싼
실패 모드다.**

## 재발방지

1. **증상과 원인의 분리 표기 강제.** 베타/감사 리포트에서 관측된 문장은 `증상:`으로만 기록하고,
   `근본원인:`은 코드 근거(파일:줄)가 첨부된 경우에만 쓸 수 있게 한다. 근거 없는 원인 진술은
   핸드오프·메모리에 승격하지 않는다.
2. **escalated 전이 시 실기 재현을 필수 단계로.** 지금은 베타 실패 → 다음 세션이 리포트 서술을
   그대로 신뢰하는 구조다. `escalated(beta_failure)`는 "원인 미상"으로 두고, 재현 로그
   (logcat + 스크린샷)가 붙어야 원인을 확정 상태로 바꾼다.
3. **검증 갭의 정의를 교정한다.** 실제 갭은 "데스크톱 ↔ WebView"(플랫폼)가 아니라
   **"스크립트 입력 ↔ 사람의 반응 지연"**(시간)이었다. 따라서 이전 세션이 제안한
   "에뮬레이터 스모크 게이트"는 이 유형을 잡지 못한다 — 스모크도 스크립트 입력이기 때문이다.
   대신 무입력 생존 시간을 검사하는 `idle-survival.node.mjs`가 필요하다(상세는 관련 노트).
